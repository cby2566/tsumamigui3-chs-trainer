# 功能说明

一个面向 AliceSoft **System4 引擎**（32 位）的数值修改器，两种改法并存：

- **内存模式**：附加进程后实时读写，改完立刻生效
- **存档模式**：直接改 `.asd` 存档，回游戏读档生效，不需要进程在跑

所有游戏身份（目录、进程名、存档路径）都外置在 `config.json`，代码里不写死；
`config.example.json` 是模板。

---

## 1. 运行要求

| 项 | 要求 |
|---|---|
| 系统 | Windows |
| Python | 3.13，且**必须带 tkinter 和 numpy** |
| 游戏 | 32 位进程（本工具按 32 位地址空间读写） |

`run.py` 会自动检测依赖；缺依赖时会尝试切到已知可用的解释器，
找不到就打印提示退出。

```bash
python run.py
```

---

## 2. 配置

复制 `config.example.json` 为 `config.json`，按实际情况改：

| 字段 | 说明 |
|---|---|
| `title` | 窗口标题 |
| `game_dir` | 游戏安装目录（静态分析工具用它找 `.ain`） |
| `exe_name` | 游戏进程名，如 `Game.exe` |
| `save_dir` | 存档目录（`SaveData`） |
| `backup_saves` | 是否在首次定位前自动备份存档目录 |
| `var_ids` | 变量号覆盖表，不同游戏版本可能需要改 |

`var_ids` 不填也能跑，代码里有默认值（按本作实测）。

## 3. 内存模式

点右上角「附加游戏」，工具会扫描一次内存里的**变量槽表**，
按变量号把所有数值一次性绑定好（约 0.5 秒），不用手工搜数字。

### 3.1 页签

| 页签 | 数值 | 范围 |
|---|---|---|
| 金币 | 游戏货币 | 0 ~ 999999 |
| 精力 | 行动力 | 0 ~ 20 |
| 日期 | 剧情日期（存的是“从 1 月 1 日起的天数”） | 天数，界面会给可读换算 |
| 受精值 | 按女主分点位，共 7 个 | 海夕里 150 / 砂夜子 250 / 藍 100 / 菫 999 |
| 愛盾 | 海夕里、砂夜子各一个 | 0=盾破、1=盾在 |
| 存档 | 见第 4 节 | — |

受精值是一个二级页签，里面再按女主/序号分。

### 3.2 每个数值页的操作

1. **定位**：一般不用点——附加时已经自动定位好了。
   只有地址失效、或换了一个游戏版本时才需要手动：把游戏里显示的数字填进来，点「定位」。
2. **候选地址**：列出所有符合的结构，默认选中已绑定的那个。
3. **修改**：填目标值点「设为」，或用「加满 / +1 / -1」。
4. **锁定**：勾上后会持续回写，游戏把值改掉就会立刻改回来。

### 3.3 自动重定位

读档时游戏会销毁并重建数值对象，期间读不到值。读档完成后点顶部
「重新自动定位」：

- 先清空旧的地址再重建，避免绑到已释放的内存
- 一次没命中会每 1.5 秒重试，最多 10 次（约 15 秒）
- 20 秒还没有结果就放弃等待，界面不会被卡住

## 4. 存档模式（离线改档）

不碰进程内存，改的是 `.asd` 文件。适合两种情况：

- 游戏没开，想先改好
- 运行时找不到的字段（变量号未知）

### 4.1 用法

1. 打开「存档」页签，左边会列出存档目录里的所有槽位（按修改时间排序）
2. 选一个，右边显示可改字段：
   - 基本：金钱、精力、日期（天数）、时段
   - 女主：等级、愛盾、受精、关系
3. 改完点「保存到存档」

### 4.2 安全机制

- 写入前把原档整份备份到 `SaveData/backup_改档/时间戳_原文件名`
- 写完重新解析，逐字段回读校验；不一致就报错并告诉你备份在哪
- 改完要**回游戏重新读一次档**才生效（游戏不会自动重读文件）

---

## 5. 两种模式怎么选

| | 内存模式 | 存档模式 |
|---|---|---|
| 生效时机 | 立即 | 回游戏读档 |
| 需要游戏在跑 | 是 | 否 |
| 受地址漂移影响 | 会（工具有自动重定位） | 不会 |
| 能改的字段 | 10 个数值 + 2 个愛盾开关 | 基本参数 4 项 + 4 位女主各 4 项 |
| 风险 | 写错地址可能让游戏异常 | 改坏存档，但有备份 |

## 6. 静态分析工具（`tools/`）

不需要游戏在跑，用来读游戏的 `.ain` 脚本数据。

| 工具 | 用途 |
|---|---|
| `tools/analyze_cint.py` | 反汇编数值相关的函数，看上限和校验方式 |
| `tools/ain.py` | `.ain` 容器解析（函数表 / 结构体表 / 全局变量表） |
| `tools/disasm.py` | 按函数名反汇编 |
| `tools/live_check.py` | 需要游戏在跑：列出内存里所有像数值结构的地方 |

```bash
python tools/analyze_cint.py
python tools/live_check.py
```

## 7. 常见现象

**改完游戏界面没变**
内存改了但游戏不会重绘。关掉状态栏再打开，或者让游戏自己刷新一次。
不要照着界面上的旧数字重新定位——会搜不到。

**读档后所有数值都读不出来**
正常现象，读档过程中数值对象在重建。点顶部「重新自动定位」。

**某个数值显示“数据不自洽”**
存储结构里的两个校验码对不上（可能是游戏写到一半被读到）。
在该页签点一次「设为」，会写回一份自洽的数据，值不变。

**自动定位没命中**
可能是读档还没结束，或者这个版本变量号不同。
可以先在 `config.json` 的 `var_ids` 里覆盖，或者用「存档」页签绕过。

## 8. 目录结构

```
run.py                 入口（自动切解释器）
config.example.json    配置模板
core/                  核心逻辑（内存读写、数值编解码、变量槽、存档解析）
ui/                    tkinter 界面（每个页签一个模块）
tools/                 静态分析工具
tests/                 自检（不需要游戏，部分用例需要存档）
report/                引擎指令表原件（供解析用）
```

## 9. 自检

```bash
python tests/test_ain.py        # .ain 解析
python tests/test_cint.py       # 数值编解码
python tests/test_session.py    # 自动定位的重建语义
python tests/test_scan_guard.py # 扫描器不会卡死
python tests/test_rsave.py      # 存档解析与写入（需要 config.json 里有存档目录）
```
